# PMM v0.6.1

自检修复版（WSL 全命令面回归测试发现的问题）。

## 修复
- **帮助文本在 Linux/macOS 显示 Windows 语义**：`help` 里 `-p<drive>` / `<BASE>:\.pmm`
  改为按平台显示 `-p <path>`（用户级安装到指定路径），`config:` 行同样按平台说明
  （Unix：`/etc/pmm` 系统模式 / `-p <path>` 用户模式）。同时补上 `--offline`、`-y` 选项说明。
- **`.pdm` 安装校验提示打印 `(null)`**：`pdm.c` 用 `msg.checksum-ok`（格式含两个 `%s`）
  却不传参，现改为独立的 `msg.verify-ok`（"checksum OK"）。
- **PATH 被塞入无关目录**：`dir_has_exec` 在 Unix 上只要目录里有任意文件就算“有可执行文件”，
  导致 `cache/`、`installed/`、`lang/` 被写进 PATH。现要求文件带可执行位（`+x`）。
- **重复刷新 PATH**：`.pdm` 安装路径里 `pmm_add_to_path` 被调用两次（`install_path` 与
  `pdm_install_file` 各一次），重复写 `~/.bashrc`、重复打印。移除多余的一次。
- **`-q` 静默无效**：全局 flag 解析顺序在 `-p` 提示之后，导致 `-q` 抑制不了
  "install path set to ..."。改为先解析全局 flag 再处理 `-p`。
- **安装类选项不能前置**：`pmm --offline install X` / `pmm -y install X` 之前会报
  "unknown command '--offline'"。现 `--offline/-o`、`--no-cache`、`--force`、`-y/--yes`
  可作为前置全局 flag。
- **`-p` 用法报错更明确**：
  - `pmm -p`（缺路径）→ `[E1] -p 需要一个路径参数`；
  - `pmm -p install x`（把子命令当路径，正是之前的踩坑）→ 明确提示
    “-p 后面要跟安装路径, 但 'install' 是子命令”，并给出正确写法 `pmm -p <路径> install <包>`。
- **系统模式非 root 的误导报错**（上一版已发现）：安装 `.pdm` 时若因写不了 `/etc/pmm`
  失败，原来误报 `cannot read <源文件>`；现改为 `[E11] 无法写入临时目录 /etc/pmm
  (系统模式需要 root/写权限)`，并提示用 `sudo` 或 `-p <路径>` 用户级安装。

## 健壮性
- **JSON 解析失败会导致无限递归爆栈**：`json_parse` 失败时 `fail()` 走 `pmm_tr` →
  `pmm_tr` 又解析内置语言表 → 再次 `json_parse` 失败 … 栈溢出（段错误）。
  现在 `fail()` 直接写 stderr（不再回调 i18n），并在 `pmm_tr` 加解析重入守卫，
  任何语言表/数据损坏都只会报错退出，不再崩溃。
